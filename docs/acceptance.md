# First two real asset journeys

These checks implement AssetQ R2-R8. They are required outcomes; revision-specific evidence below distinguishes observed runs from remaining qualification.

## Image through a worker

Submit an original wooden-crate brief and constraints through API/CLI; receive a durable job ID. An AgentQ worker qualified for `image_generation` uses its image-generation tool and returns a real bitmap. Persist the original, preview, hash, dimensions, prompt/attachment identities, method/runtime version and reported or explicitly unknown usage.

Read job progress and retrieve the verified image after the originating chat ends. Confirm the download hash matches the committed manifest. An unavailable image tool is a capability refusal, never fake success. Each runtime AgentQ qualifies for this capability is a separate implementation, not an automatic fallback.

## 3D from the generated image

Submit that image's immutable asset ID with the explicit Meshy prop recipe. Record the provider request and ID, wait without retaining an agent slot, import source GLB and texture files, and run headless Blender validation/rendering.

Report actual triangles versus target, component count, dimensions, textures, GLB parse/render outcome, elapsed times and spend. Retrieve the complete verified result from the managed pds18 store. Present the textured model renders and source image for owner judgment; valid file structure does not prove likeness or product acceptance.

## Failure and recovery proof

| Risk | Required evidence |
|---|---|
| Duplicate or conflicting input | Same key returns the original job; changed payload is refused |
| Lost provider submission reply | Reconcile the original operation or stay uncertain; no blind second paid submission |
| Executor/service crash | Recover the durable job after restart with fenced ownership and unchanged method |
| Hours-long provider work | Fake clock/provider traces cover long waits; bounded real polling and restart proof preserve the provider ID |
| Cancel during remote work | Show requested versus confirmed state and actual/unknown cost |
| Partial file import or full disk | No successful manifest or deletion of prior committed assets; safe resumed import |
| Foreign project or invalid file path | Refuse unauthorized reads/writes and caller-chosen storage paths |
| Optimizer absent/disabled | Plain worker runs; existing auth/model/permissions remain unchanged |
| Protected runtime upgrade | Original method/asset versions retain their pins; composed consumer proves fresh authority, handshake, filesystem/network/child boundaries, control/outside denial, interruption and same-operation recovery separately from upstream adapter checks |
| Current image capability | Check the actually resolved native client/tool and artifact path; old bitmap provenance or an image item in a protocol schema alone does not prove present tool availability |
| Telemetry outage | Local job/result truth survives and incomplete metrics remain explicit |
| Deferred initial backup work | Preserve existing host backups; no backup-driven stop/restart, cold-backup timer, rotation or new platform |
| Deferred backup/restore qualification | New local and independent external qualification are nonblocking for initial delivery and remain unknown; claim verification only with consistent snapshots, isolated restore/hashes and authenticated retrieval evidence for that scope |
