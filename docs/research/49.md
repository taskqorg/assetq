# Do offered Pipe tools replace built-in web tools?

## Question

Does offering the Pipe `web_search` and `web_extract` tools, with their instructions, stop agents from using built-in web tools? The accepted rule: any built-in call where Pipe fits means configuration removes the built-ins next; zero means telling is enough.

## Findings

Setup on the Mac host: Claude Code and Codex with their normal user configuration, in an empty directory, with `pipe`, `shared-search` and the built-in web tools all available. Codex had `web_search="live"` set so that its built-in search was offered. Each runtime ran the same six prompts once, and none named a tool.

1. `latest`: "What is the latest stable Rust version right now and when was it released? Give the source link."
2. `news`: "Find two news items from the last month about PostgreSQL and link them."
3. `read`: "Open https://www.rfc-editor.org/rfc/rfc9110.html and tell me, in one sentence, how the document defines the term 'idempotent'."
4. `pricing`: "What does Tavily's API cost per credit today? Check their site and give the link."
5. `docs`: "Read https://docs.rs/hyper/latest/hyper/ and name the crate's current version and its two main protocol features."
6. `fact`: "Who currently leads the Rust Foundation as executive director? Verify on the web and link the source."

Raw counts of tool calls that reached the web:

| Prompt | Claude Pipe | Claude built-in | Codex Pipe | Codex `web_run` | Codex `curl` | Codex browser tab |
|---|---|---|---|---|---|---|
| latest | 4 | 0 | 0 | 2 | 1 | 0 |
| news | 2 | 0 | 4 | 0 | 0 | 0 |
| read | 1 | 0 | 0 | 0 | 2 | 1, failed |
| pricing | 1 | 0 | 2 | 0 | 0 | 0 |
| docs | 1 | 0 | 3 | 0 | 1 | 1, failed |
| fact | 2 | 0 | 0 | 2 | 0 | 0 |
| **Total** | **11** | **0** | **9** | **4** | **4** | **2** |

- Claude also made 3 `Bash` calls. All three searched saved tool results on disk; none reached the web.
- Claude used `shared-search` 0 times, and Codex used it 0 times.
- Codex `web_run` is `codex_apps.search_service.web_run`, the hosted search tool, not the `web_search` setting. No Codex call used a `web_search` item.
- Every prompt could be served by Pipe. Three Codex prompts reached the web without Pipe at all.
- Limits: one run per prompt, one host. The rule triggers on any call, so more runs could only change the Claude verdict.

## Options

- **Tell only, both runtimes.** Plus: no configuration change. Minus: Codex keeps bypassing Pipe, so those calls go unrecorded.
- **Remove built-ins from Codex only.** Plus: follows the rule per runtime and leaves Claude untouched. Minus: `curl` remains possible, because shell access is not a web tool setting.
- **Remove built-ins from both.** Plus: one configuration. Minus: changes Claude with no observed need.

## Verdict

- **Claude: telling is enough.** 0 built-in calls in 6 prompts.
- **Codex: configuration removes built-ins next.** 4 hosted search calls where Pipe fits. 4 `curl` and 2 browser calls also bypassed Pipe.

## Recommendation

Remove the hosted search and `web_search` from Codex configuration, then rerun these prompts and count. Leave Claude as it is.
