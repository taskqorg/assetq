## Authority and inputs

Pipe R10 limits the pinned TaskQ adapter to existing-operation observation, cancellation, reconciliation, slot release and retained import. New `image-qualify`, `image-serve` and protected launch paths refuse before native effects. The qualification recipes below describe the retained implementation and historical evidence; they cannot authorize a new run. An independent AgentQ/CoreQ adapter must qualify before those paths reopen.

New project registries seed experimental `image.worker.v1@5` for the structured runtime pipeline and retain unchanged versions 2, 3 and 4. Version 1 stays disabled and immutable. `ASSETQ_IMAGE_WORKER_ROOT` names an operator-selected workspace for observing retained operations; omitting it leaves the provider unavailable. New generation launches refuse with `capability_unavailable` until composed Mac consumer and current image-tool qualification satisfy R3 and [permission authority](https://github.com/taskqorg/specq/blob/537db47c9f01c17d8cf6259a3698d8bd15435d16/engineering/permission-authority.md). There is no environment switch or request override for this refusal. The [single approved local qualification](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/bounded-image-job.md) uses a separate operator command bound to an already accepted job ID; it does not enable general dispatch.

Requests cannot choose executable, account, model, permissions, environment, output paths or optimization. The prepared native app-server path uses inherited settings, with AgentQ optimization intent `inherit`; absent optimization remains a plain native worker. Its tool/output path has one bounded owner-authorized qualification; reusable project dispatch remains incomplete.

AgentQ #186/PR188 supplies the protected app-server API; #193/PR195 corrects its receipt lookup to the producer's `authority.resolved.effective` while retaining authority and incarnation checks. The [original blocker](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/blockers/4-protected-launch.md) is historical diagnosis; its upstream implementation is published. PM qualified composed Pipe transport/boundaries at exact source `05476e88` using existing operator authority and the pinned staged Mac adapter. The [bounded native run and recovered import](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/native-size-import.md#native-operator-result) establish current image-tool/output and durable lifecycle evidence for the approved operator-bound route; the [lifecycle draft](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/blockers/4-protected-lifecycle.md) records the historical API gap. AgentQ now publishes preparation/reconciliation primitives; Pipe now integrates runner-bound slot acquisition, independent preparation and original-operation reconciliation for that single job. Its bounded native qualification is recorded with the source and import jobs. No new Windows grant or Pipe policy store is introduced.

The compiled adapter digest selects the exact signed installed TaskQ `4.6.66-261103-26` candidate; its [qualification record](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/taskq-adapter-candidate.md) distinguishes current policy compatibility and bounded native proof from unknown source/build CI mapping, and retains the prior anchors. This refresh is for bounded qualification; the separate approved image job does not enable ordinary generation. Existing registry specifications and completed provenance stay unchanged; old qualification recovery uses its preserved original binaries rather than a digest fallback.

The worker resolves attachment IDs through the job's project, verifies store hashes, and accepts PNG image references only. It passes these verified immutable files as `Part::Image` alongside `Part::Text` through `Runtime::input`. `Runtime::account` must report `Login::Subscription` before input; API key, absent or unknown identity cannot authorize input. Native wire formats and read-only account exchange belong to AgentQ. Parameters are bounded `max_width` and `max_height` (64..4096, default 4096); one original PNG of at most 16 million pixels and the configured upload-byte limit is supported. Preview PNGs fit 512 by 512. Unsupported input or absent native image generation is an explicit `capability_unavailable` refusal; no paid API or Claude fallback is selected.

## Durable operation

Use the existing executable lifecycle in `src/model.rs`: dispatch intent precedes the provider call, an acknowledged operation releases the executor lease, and completion precedes import/validation/manifest commit. A server-owned spool under the store's counted temporary directory binds the effect UUID to one runner. The detached `pipe image-turn <effect>` runner uses AgentQ's native app-server transport and a private, bounded journal. A create-once launch marker prevents duplicate runners. An incomplete launch receipt remains unknown. A sealed absence prevents a delayed old submission, as for the existing provider contract.

The runner journals runtime input/cancel intent before calling the trait, retains a private runtime checkpoint and journals native progress before importing any tool output. AgentQ owns the native handshake, wire encoding and account read. The non-generating qualification command now uses the same Runtime path. Its account reply contains only typed login/plan, and receive returns an events array. Catalogue reads remain available; config/command probes unsupported by Runtime explicitly refuse. Keep historical boundary receipts with their exact original binary. It never automatically approves native server requests. It preserves native thread/turn identity, image-tool item ID and artifact path, including completion events arriving before the turn-start acknowledgment. Only a matching successful terminal turn plus a successful native `imageGeneration` item can produce an image result. Original bytes must come from the selected native home's `generated_images` directory, pass full PNG decoding and the requested limits, and remain byte-for-byte unchanged. Evidence and preview are separate immutable outputs. Image-tool availability without such a receipt is unqualified.

The runner survives a control-service restart. Reconciliation reads the same effect spool and never launches a second turn. A runner interruption or missing terminal record remains unknown with a reason; a native operation is never replayed to obtain a replacement. Cancellation writes a durable request and sends one native interrupt for the accepted thread/turn. Confirmation requires native terminal interruption and verified completion of the original native operation and its descendants. Supervisor exit alone is transport evidence. The runner retains its terminal turn before cancellation, keeps Runtime alive through cancellation readback, then uses AgentQ `reconcile` with its independent pre-launch preparation. Only validated whole-scope completion followed by acknowledged original-slot release permits terminal publication and temporary reservation release. Missing completion or whole-operation/release proof keeps the job unknown and reservations charged. A completed report whose output fails validation ends failed after proof, with its precise reason and no replay. Transient observation/read failures remain distinguishable from invalid output. It publishes no terminal result from supervisor exit. A late completed image after cancellation is not imported by the lifecycle model.

One turn has a maximum 600-second generation interval, followed by at most 30 seconds observing interruption. Missing terminal evidence remains unknown. The protocol journal is bounded to 32 MiB; raw diagnostic stderr goes to the platform null device so it cannot exhaust storage. Original output and attachment bytes follow the configured upload limit and store admission. Temporary files remain charged and retained for recovery. A full store stops new dispatch/import; it does not delete existing assets.

This route requires a native ChatGPT subscription account and the inherited OpenAI/AgentQ provider; API-key authentication or another provider is refused before generation. `max_credits: 0` is a no-paid-API ceiling, not a claim of zero subscription usage. Native token usage is retained, and image-specific subscription usage remains unknown when unreported.

The registry's `native-inherited` model selector preserves ordinary native settings; the actual worker model is recorded by the native turn report. The image tool does not report a separate backend model ID in its receipt, so that backend identity remains unknown. This is not authority to select or replace either model.

## Configuration and operation

Set `ASSETQ_IMAGE_WORKER_ROOT` in the executor's protected environment to an existing absolute native worker workspace, alongside the existing database/data-root configuration, to observe retained operations. It never enables a new native launch. Before enabling dispatch, the supported host interface must resolve and read back the exact project/profile target, protected grant, approver/revision and effective read/write/network/child-process boundaries. Inherited mode names and prompt restrictions are insufficient. Do not edit grants or native permissions to bypass the refusal.

New project initialization seeds version 5 alongside unchanged versions 2, 3 and 4; an existing project retains its immutable registry. Its owner may register the spec returned by `image_worker::method` through the existing versioned method API. No installed service or ordinary native configuration is edited by this build.

After qualification and dispatch integration, use the existing CLI with `--method image.worker.v1@5`. Do not resubmit the accepted crate: its version 2 operation and original object ID remain the image-to-3D input. Use `status`, `events`, `cancel` and `result` on the retained job ID. The original is manifest `output-0`, the preview `output-1`, and native evidence `output-2`. The API's authenticated content download verifies the immutable original.

The prepared runner uses the same binary's internal `image-turn` command; that entry point also refuses new launches pending host authority integration. Its create-once marker independently prevents replay. Preserve the spool during recovery. A missing/unreadable process identity or native terminal receipt remains unknown, and manual replacement generation requires resolving the original operation first.

The actual Windows qualification and current limitations are recorded with the [crate receipt](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/README.md). Windows rename durability uses the platform write-through primitive; the qualification proves native writes/readback/restart, not a hardware power-loss experiment. Mutable observation receipts replace their prior snapshot durably on every platform; create-once launch markers and sealed original identities remain separate and cannot be replaced. The [Windows reconciliation regression](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/windows-receipts.md) records the replacement failure and fix.

The [protected consumer recipe](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/protected-consumer.md) supplies one bounded `image-qualify` command for PM, using the image runner's actual protected launch and native exchange functions. `image-observe` reconciles its original host operation without relaunch or slot release. This non-generating command does not enable generation or prove current image-tool availability. The separate `image-serve` command automates slot/preparation/reconciliation only for the one operator-bound qualification job.
