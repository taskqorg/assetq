## Authority and inputs

Pipe R10 removes TaskQ from this path. `image-qualify`, `image-serve` and protected recovery use only the pinned signed AgentQ adapter and Pipe permits ([evidence](evidence/47/README.md)). Both launch commands stay operator-only; neither enables general dispatch.

New project registries seed experimental `image.worker.v1@5` for the structured runtime pipeline and retain unchanged versions 2, 3 and 4. Version 1 stays disabled and immutable. `ASSETQ_IMAGE_WORKER_ROOT` names an operator-selected workspace for observing retained operations; omitting it leaves the provider unavailable. New generation launches refuse with `capability_unavailable` until composed Mac consumer and current image-tool qualification satisfy R3 and [permission authority](https://github.com/taskqorg/specq/blob/537db47c9f01c17d8cf6259a3698d8bd15435d16/engineering/permission-authority.md). There is no environment switch or request override for this refusal. The [single approved local qualification](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/bounded-image-job.md) uses a separate operator command bound to an already accepted job ID; it does not enable general dispatch.

Requests cannot choose executable, account, model, permissions, environment, output paths or optimization. The prepared native app-server path uses inherited settings, with AgentQ optimization intent `inherit`; absent optimization remains a plain native worker. Its tool/output path has one bounded owner-authorized qualification; reusable project dispatch remains incomplete.

AgentQ #186/PR188 supplies the protected app-server API; #193/PR195 corrects its receipt lookup to the producer's `authority.resolved.effective` while retaining authority and incarnation checks. The [original blocker](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/blockers/4-protected-launch.md) is historical diagnosis; its upstream implementation is published. PM qualified composed Pipe transport/boundaries at exact source `05476e88` using existing operator authority and the adapter pinned at that time. The [bounded native run and recovered import](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/native-size-import.md#native-operator-result) establish current image-tool/output and durable lifecycle evidence for the approved operator-bound route; the [lifecycle draft](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/blockers/4-protected-lifecycle.md) records the historical API gap. AgentQ now publishes preparation/reconciliation primitives; Pipe now integrates runner-bound permit acquisition, independent preparation and original-operation reconciliation for that single job. Its bounded native qualification is recorded with the source and import jobs. No new Windows grant or Pipe policy store is introduced.

The compiled adapter digest, detached signature and publication key select the AgentQ #266 macOS arm64 artifact. Pipe #61 qualified its non-generating transport and recovery. The composed Pipe consumer and current image tool still need the live run recorded in the [evidence](evidence/47/README.md). Existing registry specifications and completed provenance stay unchanged.

The worker resolves attachment IDs through the job's project, verifies store hashes, and accepts PNG image references only. It passes these verified immutable files as `Part::Image` alongside `Part::Text` through `Runtime::input`. `Runtime::account` must report `Login::Subscription` before input; API key, absent or unknown identity cannot authorize input. Native wire formats and read-only account exchange belong to AgentQ. Parameters are bounded `max_width` and `max_height` (64..4096, default 4096); one original PNG of at most 16 million pixels and the configured upload-byte limit is supported. Preview PNGs fit 512 by 512. Unsupported input or absent native image generation is an explicit `capability_unavailable` refusal; no paid API or Claude fallback is selected.

## Durable operation

Use the existing executable lifecycle in `src/model.rs`: dispatch intent precedes the provider call, an acknowledged operation releases the executor lease, and completion precedes import/validation/manifest commit. A server-owned spool under the store's counted temporary directory binds the effect UUID to one runner. The detached `pipe image-turn <effect>` runner uses AgentQ's native app-server transport and a private, bounded journal. A create-once launch marker prevents duplicate runners. An incomplete launch receipt remains unknown. A sealed absence prevents a delayed old submission, as for the existing provider contract.

The runner journals runtime input/cancel intent before calling the trait, retains a private runtime checkpoint and journals native progress before importing any tool output. AgentQ owns the native handshake, wire encoding and account read. The non-generating qualification command now uses the same Runtime path. Its account reply contains only typed login/plan, and receive returns an events array. Catalogue reads remain available; config/command probes unsupported by Runtime explicitly refuse. Keep historical boundary receipts with their exact original binary. It never automatically approves native server requests. It preserves native thread/turn identity, image-tool item ID and artifact path, including completion events arriving before the turn-start acknowledgment. Only a matching successful terminal turn plus a successful native `imageGeneration` item can produce an image result. Original bytes must come from the selected native home's `generated_images` directory, pass full PNG decoding and the requested limits, and remain byte-for-byte unchanged. Evidence and preview are separate immutable outputs. Image-tool availability without such a receipt is unqualified.

The runner survives a control-service restart. Reconciliation reads the same effect spool and never launches a second turn. A runner interruption or missing terminal record remains unknown with a reason; a native operation is never replayed to obtain a replacement. Cancellation writes a durable request and sends one native interrupt for the accepted thread/turn. Confirmation requires native terminal interruption and verified completion of the original native operation and its descendants. Supervisor exit alone is transport evidence. The runner retains its terminal turn before cancellation, keeps Runtime alive through cancellation readback, then uses AgentQ `reconcile` with its independent pre-launch preparation. Only validated whole-scope completion followed by release of the original permit permits terminal publication and temporary reservation release. Missing completion or whole-operation/release proof keeps the job unknown and reservations charged. A completed report whose output fails validation ends failed after proof, with its precise reason and no replay. Transient observation/read failures remain distinguishable from invalid output. It publishes no terminal result from supervisor exit. A late completed image after cancellation is not imported by the lifecycle model.

One turn has a maximum 600-second generation interval, followed by at most 30 seconds observing interruption. Missing terminal evidence remains unknown. The protocol journal is bounded to 32 MiB; raw diagnostic stderr goes to the platform null device so it cannot exhaust storage. Original output and attachment bytes follow the configured upload limit and store admission. Temporary files remain charged and retained for recovery. A full store stops new dispatch/import; it does not delete existing assets.

This route requires a native ChatGPT subscription account and the inherited OpenAI/AgentQ provider; API-key authentication or another provider is refused before generation. `max_credits: 0` is a no-paid-API ceiling, not a claim of zero subscription usage. Native token usage is retained, and image-specific subscription usage remains unknown when unreported.

The registry's `native-inherited` model selector preserves ordinary native settings; the actual worker model is recorded by the native turn report. The image tool does not report a separate backend model ID in its receipt, so that backend identity remains unknown. This is not authority to select or replace either model.

## Protected capacity

Capacity comes from Pipe's own `pipe.permits/1` permits; the host validates them and cannot release them. Each issuer key holds one permit at a time, the existing one-concurrent-job bound. Occupancy is the file `<issuer key name>.occupancy.json` beside the key, so `scripts/qualify_image.py`, which makes a new data root per run, still sees an earlier operation. A worker can write its Workspace, so a key inside the worker root refuses. A permit signs its binding with the issuer key named by `ASSETQ_PERMIT_ISSUER_KEY`, under the caller name `assetq-52-qualification` that the signed host policy already authorizes, so no policy or grant changes. Permit lifetime before first preparation stays the prior 120 seconds; occupancy survives expiry.

`src/image_worker/capacity.rs` holds the one occupancy model, and `tests/traces/capacity` replays it through `python3 scripts/check.py` and `pipe selftest`.

| State | Enters on | Leaves on |
|---|---|---|
| free | no file, or release | acquire; a second operation refuses as busy |
| held | acquire | launch intent; release, since nothing native can exist yet |
| launched | one-shot launch intent, persisted before the launch marker and native launch | verified completion only |
| completed | AgentQ-validated completion certificate and cleanup acknowledgment | release |

Cancellation acknowledgment, transport exit, crash and unknown reconciliation change nothing: launched stays occupied. A crash between intent and marker is treated as launched, because occupancy cannot be freed without proof. `image-observe <dir> --release` then refuses and names the operator step: run `image-observe <dir>`; if the host answers `launch identity absent`, remove the occupancy file by hand and keep the spool. No code path does this automatically. A durable release intent lets a repeated release succeed after a crash without freeing the next holder. A corrupt occupancy file refuses every effect. A runner that dies before intent makes `poll` report `runner ended before launch` with the `--release` command; the job itself stays unknown, never replayed.

## Operations started through TaskQ

These spools hold `slot-request.json` and take a separate path. `ASSETQ_PROTECTED_ADAPTER` names the pinned adapter. Recovery calls `reconcile_retained` or `cancel_retained` with the exact bytes of `preparation.json` and of `reconciliation.json`, or `authority.json` if no reconciliation exists; the operator must have sealed those bytes as a retained archive in the host store. Answers go to new `retained-*.json` files and never overwrite an original receipt.

Pipe has no path to a TaskQ slot. A terminal result needs retained `completed` and the operation's own earlier `slot-release.json` acknowledgment. `image-observe --release` answers `confirmed` with `pipe_released: false`, because Pipe released nothing. Otherwise the job stays unknown with reservations charged. Consumer directories from the old `image-qualify` have no preparation checkpoint and refuse with their evidence kept.

## Configuration and operation

Set `ASSETQ_IMAGE_WORKER_ROOT` in the executor's protected environment to an existing absolute native worker workspace, alongside the existing database/data-root configuration, to observe retained operations. It never enables a new native launch. `ASSETQ_PERMIT_ISSUER_KEY` is the absolute path of the private PKCS#8 issuer key, and `ASSETQ_PROTECTED_ADAPTER` the path of the pinned adapter for recovery of operations started through TaskQ. The build pins the adapter's identity; a path cannot select another one. Before enabling dispatch, the supported host interface must resolve and read back the exact project/profile target, protected grant, approver/revision and effective read/write/network/child-process boundaries. Inherited mode names and prompt restrictions are insufficient. Do not edit grants or native permissions to bypass the refusal.

New project initialization seeds version 5 alongside unchanged versions 2, 3 and 4; an existing project retains its immutable registry. Its owner may register the spec returned by `image_worker::method` through the existing versioned method API. No installed service or ordinary native configuration is edited by this build.

After qualification and dispatch integration, use the existing CLI with `--method image.worker.v1@5`. Do not resubmit the accepted crate: its version 2 operation and original object ID remain the image-to-3D input. Use `status`, `events`, `cancel` and `result` on the retained job ID. The original is manifest `output-0`, the preview `output-1`, and native evidence `output-2`. The API's authenticated content download verifies the immutable original.

The prepared runner uses the same binary's internal `image-turn` command; that entry point also refuses new launches pending host authority integration. Its create-once marker independently prevents replay. Preserve the spool during recovery. A missing/unreadable process identity or native terminal receipt remains unknown, and manual replacement generation requires resolving the original operation first.

The actual Windows qualification and current limitations are recorded with the [crate receipt](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/README.md). Windows rename durability uses the platform write-through primitive; the qualification proves native writes/readback/restart, not a hardware power-loss experiment. Mutable observation receipts replace their prior snapshot durably on every platform; create-once launch markers and sealed original identities remain separate and cannot be replaced. The [Windows reconciliation regression](https://github.com/taskqorg/assetq/blob/7388734a40502323fb34932471ed4b8f7a0d089b/docs/evidence/4/windows-receipts.md) records the replacement failure and fix.

`image-qualify` is the one non-generating operator consumer. It reads independently obtained expected identities on stdin, compares them with the host's preparation before launch, and holds its permit after cancellation. `image-observe <dir>` reads the original operation back, `--cancel` requests exact cancellation, and `--release` releases only after verified completion, or when launch intent was never recorded. Neither command launches. This command does not enable generation or prove current image-tool availability. `image-serve` automates permit, preparation and reconciliation only for the one operator-bound qualification job.
