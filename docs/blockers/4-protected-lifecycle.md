## Verified gap and ownership

The prepared AssetQ provider reserves an immutable effect, starts a detached runner and later reads `control.json`. No automatic producer supplies that runner's independent authority match requirements. The existing PM recipe supplies them privately and reconciles native/descendant completion independently. Manual qualification is supported; unattended durable generation is incomplete.

## Proposed acceptance

1. Specify and publish non-launching authority preparation through the checked adapter. Resolve only existing host configuration for the canonical registered project and actual consumer PID/creation identity/boot. Return current revision/account, approver, native executable/hash/home and effective profile hash. No native launch, slot widening or policy/configuration writes.
2. Treat prepared fields as independent equality requirements, never grants. Launch revalidates host authority, caller/slot incarnation and exact artifact. Missing, stale, revoked, changed or mismatched preparation refuses before native input; an operation receipt cannot supply its own expected authority.
3. Retain host-owned operation/descendant ownership across launch, cancellation, caller/supervisor interruption and recovery. Expose bounded same-operation completion readback through AgentQ. Completion requires conclusive end of the owned native operation and descendants; supervisor exit, root-process absence, EOF and terminal model events alone are insufficient. Otherwise return unknown and keep capacity occupied.
4. Preserve the existing immutable slot payload/key and effect identity. A consumer can release only its original slot after verified completion and must read back acknowledgment. Lost requests/readbacks reconcile the same operation; no native relaunch or uncertain replay. Never strip `TASKQ_ATTEMPT` or bypass an existing slot-CLI refusal.
5. Add deterministic regressions/traces for stale preparation and change between prepare/launch, crash before/after intent, surviving descendants after supervisor/root exit, PID reuse, duplicate/reordered observations, same-operation recovery and no replay. Preserve prior authority, artifact, fencing and grant checks.
6. Publish immutable source/artifact and green merge-result CI, then qualify only the added preparation/completion/recovery paths on the existing Mac Workspace route through PM. Reuse unchanged composed handshake/boundary receipts. No model turn, paid effect, crate replay, new grant, Full fallback, ordinary installation or account/model/capacity change.

## AssetQ continuation and current capability

After publication AssetQ owns runner-bound slot admission, durable preparation/control persistence, same-operation observation and acknowledged release. Persist the original private key/binding before reserve, reconcile uncertain reservation and bind to the detached runner rather than its transient executor. Service/chat termination must not end or lose the job. The supported host identity source remains authoritative.

Current image-tool availability and output provenance are a separate AssetQ acceptance gap. The [official app-server protocol](https://developers.openai.com/codex/app-server) documents provider capabilities, experimental features, skills and MCP status, but this inspection found no documented general built-in image-tool catalogue read. A feature flag, schema item, skill or MCP list does not establish availability of the actual native image tool. Do not add speculative probes or perform another generation to resolve this uncertainty. PM should retain an attributable current-client tool-discovery receipt if supported; unavailable discovery remains explicit unknown. The historical successful image item and bitmap remain valid historical evidence, never proof of this current Mac client.
