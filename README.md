# Pipe

Any external service call by an agent is a pipeline, even with one step. Agents hold no service keys. Submit text and attachments to Pipe, follow a durable pipeline job, and retrieve verified outputs; assets are one output kind. Versioned methods record how assets are made, what they cost, and why a method is recommended.

Planned site and API: `https://pipe.ufobe.com`, with asset previews/search, generation controls, method management and pipeline benchmarks. Deployment and browser/API qualification are pending.

Initial examples: an image generated by an AgentQ worker with a qualified `image_generation` capability, then an image-to-3D prop through Meshy and headless Blender.

Stage: the durable service, CLI, browser workspace, method registry and object store are implemented. General provider dispatch stays refused; bounded operator examples have separate [qualification records](src/method-evidence.json). Browser, host and provider qualification must name the exact candidate and path.

Run `python3 scripts/check.py` with Python 3, Git, a Rust toolchain and PostgreSQL server binaries (`initdb`, `pg_ctl`; set `ASSETQ_PG_BIN` if they are not found). The gate fetches the exact pinned public specq revision into ignored `.specq`, checks this contract and whitespace, then runs `cargo fmt --check` and `cargo test` against a disposable PostgreSQL cluster. CI also checks PR and merge-queue candidates. `python3 scripts/candidate.py` builds the checksum-verified release candidate.

Development checks and fixture prerequisites: [testing](docs/testing.md).

The package and command are `pipe`; existing `ASSETQ_*` configuration and storage identities stay unchanged. A live host may retain its existing `assetq` executable path through the deployment tool, which copies verified `bin/pipe` bytes only to the path bound in its host plan. No general `assetq` binary is packaged. See the [rename handoff](docs/rename-to-pipe.md) for legacy callers and the future repository move.
